Every issue here has a test that ran and passed in the run recorded at the
bottom. Two of them did not, until this commit — that is written up honestly
below rather than quietly repaired.

  #1005  A native <dialog> sample opened with no way to close it. The dialog
         behavior only built a close button for dialogs it created itself, so
         every authored one left Escape as the only exit — undiscoverable, and
         absent entirely on a sample that disables it.
         tests/regression/dialog-samples-have-close-and-padding.spec.ts, 3/3

  #1003  The panel showed rendered internals as though they were the API, and
         five trigger-button helpers wrote their styling through
         element.style.cssText, which beats every stylesheet and left the page
         unable to size its own buttons. Those declarations now live in
         src/styles/behaviors/trigger-buttons.css.
         tests/regression/demo-never-shows-expansion.spec.ts, 2/2

  #1023  The language badge (HTML / JAVASCRIPT / CSS) sat on top of line 1 of
         every code sample. The 2rem of room .x-code--has-badge reserves was
         overwritten twice: the highlight.js theme <link> is appended at RUNTIME
         so its `.hljs { padding: 3px }` is later in the cascade at equal
         specificity, and the badge rules were declared above .x-code--block,
         whose `padding: 1rem` then took padding-top back. Fixed by pairing the
         selectors with .hljs (0-2-0) and moving them below the block rule —
         specificity and source order, no !important.
         tests/regression/code-language-badge-clears-first-line.spec.ts, 1/1

  #1020  The behaviors workspace had two scrollbars a few pixels apart, no gap
         at the side, and a footer John asked to remove. The workspace was sized
         off the VIEWPORT while living inside a container that is not the
         viewport, so it overflowed .site__body and both scrolled. It takes its
         height from the container now, through a flex chain where every link
         carries min-height: 0.
         tests/regression/behaviors-workspace-single-scroll.spec.ts, 3/3

  #1031  sticky.js crashed on an element removed mid-scroll: createPlaceholder()
         runs from the scroll handler and assumed the host still had a parent,
         so a re-rendering page threw "Cannot read properties of null (reading
         'insertBefore')" and aborted the rest of that pass. It guards now, and
         STOPS TRACKING a detached host — a listener still firing for a dead
         element is why the error repeated on every subsequent scroll rather
         than happening once.
         tests/regression/x-sticky-behavior.spec.ts — the scroll-then-detach
         case added here passes. The spec's four OLDER cases still fail; they
         are pre-existing entries in data/test-baseline-failures.json, were
         failing before this change, and are not caused by it.

  #1036  x-table sorted on displayed text only, so a column could not sort by
         anything but what it shows. The issues table renders "—" for an unrated
         priority, and ascending order put every unrated row above priority 1 —
         least urgent first, in the column that exists to express urgency.
         tests/regression/x-table-sort-value.spec.ts, 3/3

TWO TESTS THAT CLAIMED A PASS THEY NEVER HAD

The batch this replaces asserted that every issue's test "ran and passed in the
last recorded run". For two of them that was untrue, and both were test defects,
not product bugs. Re-running the five cited specs is what surfaced it: 9 passed,
8 failed.

#1036's spec mounted into /tests/fixtures/blank.html and then waited 20 seconds
for window.WB. That fixture's own comment says it deliberately ships no WB
bootstrap, so the wait could never resolve — all three cases timed out, and the
spec had never passed once. It mounts on the site root now, the pattern
no-inert-behaviors.spec.ts already uses.

#1036's FIX was also wrong where it counted. It read `cell.dataset.sortValue`
and made `data-sort-value` the authoring surface: a `data-` attribute on a
behavior element, read through `.dataset`, which Law 11 forbids on both counts.
The key is a plain `sort-value` read with getAttribute() — renamed in table.js,
in both cells of pages/issues.html, and throughout the spec.

#1020's spec asserted `#siteBody.scrollHeight <= clientHeight + 1` as a proxy
for "no page-level scrollbar". But the fix for #1020 IS `overflow: hidden` on
that element, and an overflow:hidden box still reports its full content size in
scrollHeight. The proxy failed on 7px of clipped content while the page had no
page-level scrollbar at all — precisely the state the test exists to protect. It
now sets scrollTop and asserts the container does not move, which is the real
invariant and does not shift with font metrics.

REGRESSIONS THIS WORK INTRODUCED, AND FIXED

#1020's first version applied at every width. Measured at 375x812: the 837-row
behaviour navigator rendered 2px tall and, since .site__body had been told not
to scroll, nothing was reachable — a frozen phone layout. The treatment now sits
inside the page's own two-column breakpoint, with a min-height floor as well:
below ~600px of window the list's own minimum and the panel's offset genuinely
conflict, and #992 requires the outer scroller to be able to reach the overflow.
