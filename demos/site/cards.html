Expandable Card

The card system uses a behavior-based architecture. Each variant is an independent behavior that composes the shared card structure and CSS — there is no base class to inherit from. Variants CONTAIN specialized content rather than inheriting it, so a change to the shared structure propagates to every variant automatically.

➕ Expandable Card

An expandable card shows the start of its content and keeps the rest behind Show More. Collapsed, it holds the content to a height (maxHeight) or to a number of whole lines (lines), so a long answer, changelog or description does not push the rest of the page down. Show More releases the limit and the card grows to fit everything; Show Less puts the limit back. The button reports its state through aria-expanded, so a screen reader announces whether the content is open. Keyboard users can toggle it with Enter or Space. When the content already fits inside the limit there is nothing to reveal, so the card shows no button at all. Resize the window or change the content and the card checks again, bringing the button back once something is hidden. Set lines to clamp the collapsed card to that many whole lines of text; when both lines and maxHeight are set, lines wins. Without either, the collapsed limit is a maxHeight of 100px. Add the expanded attribute to start the card open, with the button already reading Show Less. Every click flips the label between Show More and Show Less and flips aria-expanded with it, so the visible text and the announced state never disagree.

The limit is a ceiling, not a fixed size: content shorter than it simply ends, and the card shows no button. Use lines instead of maxHeight when the content is plain text, so the cut always falls between two whole lines rather than through the middle of one.
