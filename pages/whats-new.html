🆕 What's New

What's actually live on this site right now — every push to main deploys straight to cielovistasoftware.github.io/wb-starter, so this list is the real changelog, not a promise of a future release.

3.0.77 — 2026-08-21

This is what is live at 3.0.77.

  • Bug Input variants and sizes were dead on every host. Three causes, found by a permutation suite rather than one at a time: the container host built a field and applied neither, the native host read only data-size and never the plain size, and size="md" / variant="default" were skipped on purpose — leaving the schema's own defaults with no trace, indistinguishable from being ignored (#755).
  • Bug <div x-input> rendered nothing at all. The field builder was gated on the host being <wb-input>, so the documented authoring form produced no label, no field and no variant. It now builds on any container host; a host that IS a form control keeps the wrap path, where the element already is the input (#755).
  • Request A behavior that cannot honour your attributes now says so. Asking for label, helper, error or input-type on a host that cannot build a field raises a real runtime error naming the ignored attributes, instead of rendering nothing and looking broken (#755).
  • Request The events panel reports the element id, and only the id. It printed tag#id.class, burying the one token worth reading — and because the listener sits on the stage, a click on the stage's own padding was logged as if the example had fired it. Events outside the example are no longer reported at all (#756).
  • New Permutation suites for input, and every x-* checked for impropriety. Both read their value lists from the schema and the tag-to-behavior map, so new values are covered without touching the tests. The x-* test swept 29 doc files still teaching <figure x-figure>, <img x-image>, <pre x-pre> and the rest, and the generator that would have put them all back (#754).

3.0.76 — 2026-08-21

This is what is live at 3.0.76.

  • Bug package.json and package-lock.json were empty on main for four releases. A version-bump script opened each file for writing before reading it — which truncates — so it wrote an empty string back. 3.0.71 through 3.0.75 shipped with both files blank, breaking every npm command against the repo. Restored from the last good copy and re-versioned; both parse.
  • New A test that finds every x-* attribute and rejects the improper ones. <figure x-figure> is redundant — a <figure> auto-injects the behavior from its tag — and #746 showed the redundant form can silently suppress the behavior entirely. The test sweeps authored pages, demos, docs and the seeded example data, and drives the showcase to check every generated example, which is the path that produced <figure x-figure> in the first place. Tag-to-behavior pairs are read from the map itself, so new mappings are covered without touching the test (#754).

Whether a tag auto-injects a behavior is a fact about the tag-to-behavior map, not about whether someone wrote a label, so the generator now asks the map (#754).

3.0.71 — 2026-08-21

This is what is live at 3.0.71.

  • Bug The form behavior never turned AJAX on. <form validate ajax> — the documented spelling — did nothing, because the behavior read only data-ajax. Submitting fell through to a plain form post, which is why nothing appeared to happen. Plain attributes are now read alongside their data-* equivalents for ajax, validate, auto-save and the three message strings, closing the same gap #697 closed for fieldset and formrow. ajax="false" is also honoured as OFF: a bare presence check reads the string "false" as ON, the opposite of what the markup says (#751, #747).

It now targets a demo endpoint that accepts and discards, so the success message and the wb:form:success event actually fire. 3.0.64 — 2026-08-21

This is what is live at 3.0.64. Both items are why recent releases looked like they had not shipped.

  • Bug The cache-bust token was always one commit behind the change it existed to bust. stamp-version.js read git rev-parse --short HEAD, which during a pre-commit run is the parent commit — the commit being made does not exist yet. So a release that changed only CSS shipped with an unchanged ?v= and never reached any browser holding the old file. Measured: 3.0.63 deployed with ?v=80d6768, which is the 3.0.62 commit. The token is now the release version (?v=3.0.64): known before the commit, changed exactly when a release ships, and named the same as the release it belongs to.
  • Bug Page content was served from cache after every deploy. The site fetched pages/<id>.html with no cache-bust at all, so the browser re-served its stored copy while the raw URL served the new file. Measured on this page: the server had the 3.0.63 content and the site rendered 3.0.61. Fragment fetches now carry the release version too — which is why this entry is visible to you at all.

2026-08-19

  • Behaviors showcase rebuilt around a live selector. Pick any behavior or variant from the list and it renders immediately beside the list, with its formatted source, its live events, the handler you would copy, and its docs — replacing the 88 hand-written demo sections that used to run down the page (#664, #666).
  • <wb-table paginated> now paginates. paginated and pageSize were declared in the schema and read nowhere, so the attribute rendered every row and no controls. Rows are hidden rather than removed, so sorting, searching and row listeners keep working on the same nodes. hoverable and filterable — the documented spellings — did nothing either, because the behavior only ever read hover and searchable; both are accepted now (#669).

Two causes, both fixed: the behaviors set border/background/color inline, which beats any stylesheet rule, so each one overrode its own variant classes; and the bare-native rules in input.css stacked up to nine :not([type=…]) selectors, outranking a modifier class on specificity. wb-input--warning was applied by the behavior but no rule ever defined it (#671).
  • Native <select> honours variant and size. The behavior early-returned for a native <select>, handling only clearable, so <select variant="error"> came out with no class at all. A numeric size="4" deliberately keeps its native "show 4 rows" meaning instead of becoming a style class (#681).

A sweep of all 105 x-* behaviors found 21 doing this; it is now 10, and all 19 card behaviors keep their content in both the <wb-*> tag and x-* attribute forms. Also closed a broader gap: the schema exclusion list that protects behaviors from being wiped was consulted only for <wb-*> tags, so every entry on it was bypassed by the equivalent x-* attribute (#678).

  • Every element in the showcase carries a stable id, and the event log names the element an event actually came from, so two events from different elements are no longer identical lines (#675, #677).
  • Striped table rows have real contrast — only the odd rows were painted, leaving the even ones transparent, so the stripe depended on whatever surface the table happened to sit on rather than on the theme (#672).
